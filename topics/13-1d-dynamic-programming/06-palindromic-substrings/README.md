# 647. Palindromic Substrings

![Difficulty](https://img.shields.io/badge/Difficulty-Medium-yellow) ![Pattern](https://img.shields.io/badge/Pattern-String%20DP-blue) ![Tags](https://img.shields.io/badge/Tags-DP%2C%20String-lightgrey)
**LeetCode:** https://leetcode.com/problems/palindromic-substrings/

## Problem
Given a string `s`, count how many contiguous substrings of `s` are palindromes. Substrings at different positions count separately even if they contain the same characters.

**Input:** a string `s`
**Output:** an integer — the total count of palindromic substrings

**Examples:**
1. `s = "abc"` → `3`. Each single character (`"a"`, `"b"`, `"c"`) is its own palindrome; no longer substring is.
2. `s = "aaa"` → `6`. Palindromes: `"a"`, `"a"`, `"a"`, `"aa"`, `"aa"`, `"aaa"`.
3. `s = "aba"` → `4`. Palindromes: `"a"`, `"b"`, `"a"`, `"aba"`.

**Constraints:** `1 <= s.length <= 1000`, `s` consists of lowercase English letters.

> 🔑 **Pattern Recognition**
> Same `dp[i][j] = (s[i]==s[j]) and dp[i+1][j-1]` recurrence as Longest Palindromic Substring, but now every `True` cell contributes to a running count instead of a max-length — recognizing "counting DP" vs "optimization DP" as variations on one recurrence is the key skill here.

## Intuition (explained simply)
This is the counting cousin of Longest Palindromic Substring — same underlying structure (check if `s[i..j]` is a palindrome), except instead of tracking the longest one we tally up every single one that qualifies.

### 1. Brute Force
- Check every possible substring `s[i:j]` directly against its reverse, and increment a counter whenever it's a palindrome.
- Correct because it exhaustively enumerates and verifies all O(n^2) substrings.
- Time complexity: O(n^3)  Space complexity: O(1) extra
- The O(n) palindrome check per substring is wasteful — checking `s[i..j]` from scratch ignores that we may already know whether `s[i+1..j-1]` is a palindrome.

### 2. Better
- **DP state:** `dp[i][j]` = `True` if `s[i..j]` is a palindrome, else `False` — same as Longest Palindromic Substring.
- **Transition:** `dp[i][j] = (s[i] == s[j]) and dp[i+1][j-1]`, computed via memoized recursion (top-down): to know if `s[i..j]` is a palindrome, first resolve the smaller `s[i+1..j-1]` and cache it. Every time a `(i, j)` pair resolves to `True`, add 1 to the running count.
- Correct for the same recursive-definition reason as before: ends match AND the inside is a palindrome.
- Time complexity: O(n^2) states, O(1) each after caching  Space complexity: O(n^2) memo table + recursion stack
- The full table costs quadratic memory even though we only ever need small windows at a time; recursion adds call overhead.

### 3. Optimal
- **Core insight:** expand around every possible center (same `2n - 1` centers as before — n odd centers, n-1 even centers). Every time the expansion successfully matches a pair of characters, that's one more valid palindrome — so instead of just tracking the longest, count every successful expansion step.
- **Why it works:** for a fixed center, each successive expansion (if it still matches) produces one new, strictly larger palindrome centered there, and no palindrome is generated by more than one center — so summing successful expansions across all centers gives the exact total count with no double-counting.
- For each center, expand outward while characters match, incrementing the count by 1 on every successful match (both odd-length centers at each `i`, and even-length centers between `i` and `i+1`).
- Time complexity: O(n^2)  Space complexity: O(1) extra
- Edge cases: single character (count 1), all identical characters (count grows quadratically, e.g. `n=5` all same → 15), no repeated characters (count == n, only single-char palindromes).

Worked example: `s = "aba"` → `4`.

`dp[i][j] = (s[i]==s[j]) and dp[i+1][j-1]`. `dp[0][2]` is `True` because `s[0]==s[2]=='a'` and the inner single character `s[1..1]` is trivially a palindrome. Counting every `True` cell: `dp[0][0], dp[1][1], dp[2][2]` (the three single characters) plus `dp[0][2]` (`"aba"`) = **4** total.

## Complexity Summary
| Approach | Time | Space |
|---|---|---|
| Brute Force | O(n^3) | O(1) |
| Better | O(n^2) | O(n^2) |
| Optimal | O(n^2) | O(1) |
